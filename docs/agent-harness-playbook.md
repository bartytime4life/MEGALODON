# Agent harness for reviewing local monitoring evidence

Use harness engineering to make MEGALODON's defensive evidence easier to
interpret and verify. Begin with a synthetic, offline operator task and improve
the evidence or review process around the existing local advisory path. Keep
the deterministic detector and its receipts as the source for what occurred.
Operational model generation remains unbound. Any optional model comparison
uses the existing authorized diagnostic scope in isolation.
[Current state](current-state.md) · [Unbound runtime](qwen-runtime-unbound.md) · [AI control plane](ai-control-plane.md)

## Scope, context and verification

- Start a maintenance task with the exact checkout and the permitted scope.
  Point to the field guide, the applicable evidence/projection contract and the
  focused offline test. State the decision the operator needs and what evidence
  would justify a conclusion. Keep historical receipts attached to their
  original inputs, revision and hardware scope. [Contributing](../CONTRIBUTING.md)
- Apply the approved narrow metadata projection for the selected advisory
  policy. Preserve validated counts, source kind, timestamps or time basis,
  gaps, terminal status and the relevant rule limitations. Keep raw traffic,
  private file or host details, credentials and operator records outside model
  context and shared traces. Use the projection limits and validator at the
  existing application boundary. [Local model advisory contract](local-model-advisory-contract.md)
- Keep each model step a bounded advisory read. Validate the outcome against
  the evidence and preserve the documented abstention, denial and error
  outcomes. Operator actions remain separate and explicitly authorized.
  Use fixed fixtures and deterministic checks for the trial. [Advisory result integrity](advisory-result-integrity.md)
- Carry only the receipt identifiers, versions, open question and check result
  needed for continuity. Recheck freshness after an interruption or provider
  change. Record status, duration, omissions and reason codes without copying
  sensitive source. A separate reviewer should compare conclusions with the
  actual projection and the run receipt. [Model containment review](model-containment-review.md)

## First experiment

Take a fictional local detector run with validated counts, a partial run with
missing evidence, and a stale or unavailable input. Freeze each fixture,
question, detector/configuration version, model digest if used, and review
rubric. Compare the current presentation with one change that prominently shows
completeness, unsupported conclusions and the receipt references. Use the same
evaluator, time budget and offline permissions. If a model run is explicitly
in scope, hold the model and settings fixed. Try the presentation with the
deterministic evidence path first.

Score whether the reviewer identifies the right run/status, cites the matching
evidence, preserves uncertainty on incomplete data and reaches the same
defensible next check. Track time, corrections, no-answer outcomes and operator
interventions. Reject the candidate if supported baseline results are lost,
a material unsupported claim appears, or a refusal or offline boundary changes.
The trial can establish an interpretation benefit for its synthetic cases.
Operational detection accuracy, native host behavior and provider containment
need their separately documented evidence. [Offline layered evaluation](layered-evaluation.md)

## Reference patterns

- Add a checkpoint and independent offline review. [Learn Harness Engineering](https://github.com/walkinglabs/learn-harness-engineering)
- Keep the model prompt, permissions, bounded input and outcome validation under application control. [12-Factor Agents](https://github.com/humanlayer/12-factor-agents)
- Make the relevant offline commands and contribution limits discoverable. [AGENTS.md](https://agents.md/)
- Predefine evidence, abstention and refusal criteria. [GitHub Spec Kit](https://github.com/github/spec-kit)
- Study compaction and human checkpoints as patterns for explicit continuity. [Deep Agents](https://github.com/langchain-ai/deepagents)
- Keep the advisory sequence inspectable and short. [Mini SWE Agent](https://github.com/SWE-agent/mini-swe-agent)
- Review other implementations' trust boundaries and verify consequential claims upstream. [Awesome AI Anatomy](https://github.com/NeuZhou/awesome-ai-anatomy)
- Package frozen synthetic cases for repeatable evaluation only if existing runners need it. [Harbor](https://github.com/harbor-framework/harbor)
